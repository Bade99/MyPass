# Resize rendering diagnostics

Set `RENDER_DIAGNOSTICS_ENABLED` near the top of `src/render_diagnostics.h` to `1` for timing reports or `0` to compile the diagnostics out, then rebuild. A project preprocessor definition can override the default. No environment variables are needed at runtime.

- `selected_mode` chooses the renderer. `Mode::directwrite_gdi` is the current renderer: it keeps DirectWrite layout and hit testing, rasterizes glyphs through a cached DirectWrite bitmap target, and copies them to each control's GDI paint DC. `Mode::directwrite` uses the original Direct2D DC target for comparison.
The renderer selection is independent of the diagnostics toggle; `Mode::directwrite_gdi` remains selected when diagnostics are disabled.

Prefer a Release build for timing comparisons. Resize the editor window by dragging its edge and releasing it. Each completed resize appends one UTF-8 report to `%APPDATA%\MyPass\render-diagnostics.log`; the same report appears in Visual Studio's **Debug** Output when a debugger is attached. Repeat with the same data and approximately the same window sizes for each mode, rebuilding and restarting after each change. Each report includes a local timestamp, mode, build configuration, call counts, total milliseconds, average milliseconds, and the slowest call for each category. `resize_wall` includes time spent holding or pausing the mouse during the drag; compare the measured categories rather than wall time alone. Categories can be nested, so their totals should not be added together. The log is best-effort and does not affect the application if the folder or file cannot be written.

`window_resize` and `editor_resize` include child window placement. `card_resize_plan`, `card_resize_apply`, and `card_move` show the work done for password cards. `card_backdrop_move`, `card_header_move`, `card_toolbar_move`, and `card_table_move` isolate nested card placements; `table_cell_move`, `value_text_move`, and `value_tool_move` break down table cells and value-cell children. `text_size`, `text_paint`, `static_text`, `button_paint`, `caption_paint`, `list_resize`, `list_backbuffer`, and `background` show the principal resize and paint paths. `text_format`, `text_layout`, `dc_target`, `dc_brush`, `dc_begin_draw`, and `dc_end_draw` break down DirectWrite/Direct2D work. `dc_target_create`, `dc_target_create_failure`, `dc_bind_failure`, and `dc_end_failure` expose target creation and drawing errors. `bitmap_target`, `bitmap_target_create`, `bitmap_target_resize`, `bitmap_copy_in`, `bitmap_draw_layout`, `bitmap_draw_glyph`, and `bitmap_copy_out` time the DirectWrite/GDI path. `bitmap_failure` counts fallback to the original Direct2D path. `gdi_text` measures the fallback drawing path. Reports contain timings and counts only, not text or account data.
